# FDE 学院 · 从业务问题到可验收的交付

[在线学习](https://fde.aielsen.com/academy/zh/) · [12 周课程](https://fde.aielsen.com/academy/zh/curriculum/) · [English](FDE-ACADEMY.en.md) · [返回指南首页](../README.zh-CN.md)

FDE 的工作不是替客户演示一个更聪明的聊天框，而是在业务现场找到值得解决的问题，把产品、数据、专业判断与工程约束连起来，再证明这条工作链确实能用。

学院围绕一个合成的连锁零售会员运营项目展开：业务希望改善复购，CRM 和 POS 的身份不一致，运营不信任推荐人群，IT 需要明确权限和运行责任。课程从项目判断开始，逐步进入数据适配、建议型 Agent、受控执行、效果分析和交付复盘。

这不是零基础编程课，也不是已投入生产的 Agent 平台。工程学习者应具备 Python 或 TypeScript、SQL、HTTP API、Git 和基本测试能力；业务角色可按下方路径参与，不必承担全部代码作业。

## 一个贯穿任务：从“最近没来的会员”到可核验建议

### 1. 把模糊请求变成工具可以执行的契约

先问清门店、截止日，以及“没来”按到店还是有效购买定义。例如，练习可限定为某门店、某个快照日、距最近一次有效购买 30–90 天。这个定义是教学情境，不应直接套到真实企业。

CRM ID、POS ID、手机号与姓名不能随意当作同一个身份。身份规则有版本，冲突项进入待核对队列。无效、退款、重复和未知记录分别留下处理理由，而不是为了凑人群把它们静默丢掉。

### 2. 用工具给出证据，让模型解释业务

`segment_members` 是只读计算工具。输入包括门店、截止日、时间窗等；输出应包括人群引用、排除数量、指标版本和证据快照。真正的租户与权限来自可信上下文，不让模型通过填一个字段就冒充另一个租户。

`propose_operation` 接受合法的人群引用和规则，提出受约束的方案，不直接发券。模型负责澄清、选用工具、解释依据和表达不确定性；代码负责计算、校验、授权及执行边界。MCP 一类协议能帮助连接工具，但不能替代业务语义或权限设计。

### 3. 加入动作时，单独证明副作用可控

训练中的发券与标签是本地模拟。执行前将操作者、租户、快照、参数摘要、额度、规则版本与有效期绑定；参数变化必须重新确认。同一幂等键和同一参数应得到同一结果，同键不同参数应拒绝。

超时后结果可能是 `unknown`，应先查询状态，不能假定失败然后再发一次。预算需要在实际执行处重检。内存字典的幂等记录不等于具备重启恢复或并发事务能力；这些是进一步实现并验证的工作。

### 4. 留下可复现的证据，不只保存一张成功截图

至少记录一次正常任务、一次缺条件需澄清、一次无证据或越权拒绝，以及执行结果未知后的处理。记录输入版本、工具参数、可观察结果、业务判断与费用；不采集或要求模型的私密思维链。

最后把“机制测试通过”“真实模型完成任务”“业务接受结果”“业务效果改善”分开报告。未运行的检查写 `not_run`，不写通过。

## 动手练习：工程包能做什么，还需要你做什么

[下载工程实训包](https://fde.aielsen.com/academy/downloads/fde-practice-kit.zip) · [中文说明](../academy/practice-kit/README.zh.md) · [源码](../academy/practice-kit/)

Python 3.10+，标准库即可。进入工程包目录后运行：

```sh
python -m unittest discover -s tests -v
python demo.py
python tenant_extension.py
python evaluate.py
python analysis.py
```

| 已提供的教学机制 | 学员还需完成或证明 |
| --- | --- |
| 37 项离线测试：21 项基础机制 + 16 项租户扩展 | 接入真实模型，记录多轮工具选择与不同输入下的行为 |
| 合成 CSV、重复与异常隔离、指标计算和权限范围示例 | 真实环境中的身份鉴别、完整权限体系与数据质量责任 |
| 只读有限步工具循环、确认参数、预算、幂等与审计示例 | 持久化、事务、并发、重启恢复、真实连接器与运维 |
| 固定脚本规划器与机制评估示例 | 模型任务评估、保留测试集和失败分类；固定脚本不算 Agent 能力证明 |
| 合成业务效果分析 | 对照设计、样本限制与因果假设；示例差值不等于真实收益 |

不要向练习中填入客户资料或生产凭据。接入模型时，保留工具白名单、参数校验、权限、预算与步数限制；不要开放任意脚本、Shell 或未经审查的 SQL 执行。

## 怎样读案例，才能把方法用起来

[19 个课程案例与实作](https://fde.aielsen.com/academy/zh/cases/)与[9 个 Agent 工作案例](https://fde.aielsen.com/agent-cases/)用途不同：前者辅助课程分析与作业，后者展开一条工作如何连续推进。

每读一个案例，写下五个答案：

1. **问题**：谁在什么任务上遇到阻力？输入和成功标准是什么？
2. **发现**：怎样分辨表面诉求与真正瓶颈？有什么证据、分歧和未知？
3. **行动**：先做什么，为什么？业务专家、工具与模型如何分工？
4. **判断**：什么条件下继续、澄清、拒绝、缩小范围或转交给人？
5. **交付**：留下什么产物？换成你的场景，哪些规则和数据必须重配？

公开案例是公开事实加教学分析；合成实作是练习，不是客户业绩。不要把知名公司名称或引用资料当成自己的交付成绩。

## 结业不是“功能都点过了”，而是交得出去

准备六组材料：问题与范围、数据与语义、系统与模型、执行与运行、评估与结果、产品反馈与复用资产。用一个索引把每个主张连到代码、测试、轨迹或交付物。

建议评审维度为：业务诊断 20%、数据与语义 20%、工程与运行 20%、评估与安全 20%、结果与归因 10%、协作与复用 10%。这是教学评审建议，不是资质认证。数据泄露、伪造轨迹、模型自行授权、链路不可运行或用固定脚本冒充 Agent，不能靠其他项高分抵消。

一次有效答辩应能展示正常任务与故障路径，并接受“换一个租户、改变指标窗、接口超时、预算不足”等新约束。作品说明写清个人贡献、合成数据、已验证范围和剩余限制。
